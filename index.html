Before you build · two different jobs

A firewall and an antivirus are not the same tool

People lump them together as "security software," but they watch for completely different things, and neither can do the other's job.

Antivirus examines files

An antivirus looks at files already on the computer — a download, an email attachment, a memory stick — and decides whether each one is safe to open. Its question is: "is this thing dangerous?"

Firewall examines traffic

A firewall sits at the edge of the network and watches connections going in and out. It never opens a file. Its question is: "should this connection be allowed through?"

A member of staff downloads a file that turns out to be malware. Which tool is designed to catch the file itself?

Catching malware by its fingerprint

Every known piece of malware has been seen before by security researchers, who record a short signature — think of it as a fingerprint taken from the file's contents. An antivirus keeps a list of these fingerprints. When it scans a file, it checks: does this file's fingerprint match anything on the wanted list?

Change one byte, change the fingerprint

Attackers know their malware is on the wanted list, so they make a tiny change to the file. It behaves exactly the same, but the fingerprint is now different — and a different fingerprint doesn't match. These near-identical copies are called variants.

A fresh batch same detector, new files
Why this matters

Fingerprint matching can only catch what it has already seen. Against a changed copy it is helpless — and attackers can generate thousands of variants automatically. To catch these, your detector has to stop asking "have I seen this exact file?" and start asking "is this file behaving like malware?"

Antivirus lab · stage 3 of 5

Judging a file by what it does

Instead of matching exact files, a modern antivirus watches for suspicious behaviour. On their own, each of these actions can be innocent — but the more of them a single file does, the more suspicious it looks. This is called heuristic detection: a rule of thumb rather than a certain match.

Antivirus lab · stage 4 of 5

When honest software looks guilty

Here's the catch nobody expects. A legitimate backup tool also encrypts many documents. A genuine installer also changes system files. A cloud sync app also sends data to an outside server. Your heuristics can't tell intent — they only see behaviour.

When your detector blocks an innocent file, that's a false alarm (a false positive). Too many of these and staff can't do their jobs, so they start switching the antivirus off — which is worse than having none. Re-tune your policy with real software in the mix.

Firewall lab · stage 1 of 5

The gate at the edge of the network

Every time a computer talks to the internet — loading a website, sending an email, syncing a file — a connection is made. A firewall is the gate every connection has to pass through. For each one it makes a single yes-or-no decision: allow it, or block it.

It doesn't open files or remove viruses. It only controls which connections are permitted. The skill is deciding what to let through without accidentally blocking the things the business needs.

What does a firewall actually decide?
Firewall lab · stage 2 of 5

What the gate can actually see

A firewall can't read your emails or see inside a download. For each connection it only sees a few labels on the outside — and it has to decide from those alone. Three of them do most of the work:

The port — which service is this?

Every type of internet service has a numbered port, like a numbered door into the building. The number tells the firewall what kind of connection it is. Tap each one to see what it's for.

The direction — who started it?

Outbound means someone inside the company reached out (staff loading a website). Inbound means someone outside is trying to reach in. Unexpected inbound connections are the ones to be nervous about.

The protocol — TCP or UDP?

Just two delivery methods. TCP is used for most things where every bit must arrive (web, email). UDP is a lighter, faster method used for quick lookups. You rarely need more than the name.

Firewall lab · stage 3 of 5

Write the rules, then watch the traffic

A firewall is just an ordered list of rules. Each rule says: for this kind of connection, allow or block. The crucial part is the order — the firewall reads top to bottom and stops at the first rule that matches. Anything no rule matches is blocked by default.

Your task: let the business work (staff need web, email and address lookups) while keeping intruders out. Add rules in plain language — you'll see the real firewall version appear in the list.

What the two have in common

Neither tool is ever perfect. The antivirus trades missed malware against false alarms — tighten one and the other gets worse. The firewall trades security against staff being able to work. In both, "block more" is not the same as "safer," and each tool is blind to what the other handles. That's why real organisations run them together, in layers, rather than choosing one.

Exam-style evaluation

Evaluate the extent to which antivirus and firewall software can protect an organisation's data on their own. You should refer to how each tool works, its limitations, and reach a justified overall judgement.

A strong answer will:

  • explain what each tool checks, and the fact that it cannot do the other's job;
  • use your own results — detection rate, false alarms, blocked attacks, disrupted services;
  • explain a genuine limitation of each (variants and false positives; port ambiguity and rule order);
  • reach a judgement about layering rather than choosing a single "best" tool.
